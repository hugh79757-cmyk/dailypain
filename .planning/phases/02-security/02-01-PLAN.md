<objective>
Eliminate all SQL injection vectors, add authentication to the Worker API, replace manual secret management, and make the pipeline resilient to external API failures and malformed AI responses.

Purpose: The project currently has four classes of production-risk issues:
1. **SQL injection** — `daily_run.py` builds INSERT statements with f-strings and a custom `esc()` that only escapes single quotes.
2. **No auth** — Any client on any origin can POST data to `/api/pain` or toggle `/api/star`.
3. **Manual secret management** — Both Python scripts parse `.env` with fragile line-splitting instead of using `python-dotenv`.
4. **Brittle error handling** — Naver/OpenAI failures are silently swallowed (`except Exception: pass`); the `AttributeError` crash from 2026-03-15 (model returned string instead of dict) will recur.

Output: Auth-gated Worker, CORS-narrowed API, dotenv-based secret loading, retry wrappers on all external API calls, OpenAI response validation, HTTP-upload-based pipeline (no SQL file generation), and a rollback plan for each change.
</objective>

    ### A. Add Bearer token auth to POST endpoints
    At the top of `workers/worker.js`, after the `const url = new URL(request.url);` line, add:

    ```js
    // Auth gate: POST endpoints require Bearer token matching env.API_TOKEN
    const AUTH_TOKEN = env.API_TOKEN;
    function unauthorized(msg) {
      return new Response(JSON.stringify({error: msg || "Unauthorized"}), {status: 401, headers: {"Content-Type":"application/json"}});
    }
    ```

    In the `POST /api/pain` handler (current line 9-14): add an auth check BEFORE the try/catch. Change the route condition from:
    ```js
    if (url.pathname === "/api/pain" && request.method === "POST") {
    ```
    To:
    ```js
    if (url.pathname === "/api/pain" && request.method === "POST") {
      if (!AUTH_TOKEN || request.headers.get("Authorization") !== `Bearer ${AUTH_TOKEN}`) return unauthorized();
    ```

    In the `POST /api/star` handler (current line 29-32): add the same auth gate before `const {id}`:
    ```js
    if (url.pathname === "/api/star" && request.method === "POST") {
      if (!AUTH_TOKEN || request.headers.get("Authorization") !== `Bearer ${AUTH_TOKEN}`) return unauthorized();
    ```

    **Rationale:** POST /api/pain inserts into the database; POST /api/star toggles data. GET endpoints (read-only) remain public since the dashboard needs them. The `AUTH_TOKEN` is unset check (`!AUTH_TOKEN`) allows local dev without auth (if API_TOKEN not set) while enforcing it in production. This prevents accidentally locking out local testing.

    ---
    ### B. Narrow CORS headers — remove wildcard
    Replace the current line 4:
    ```js
    const cors = {"Access-Control-Allow-Origin":"*", ...};
    ```
    With an origin-restricted approach. Add at the top of the handler, after `const url = new URL(request.url);`:
    ```js
    const ALLOWED_ORIGINS = ["https://dailypain.hugh79757.workers.dev"];
    const origin = request.headers.get("Origin") || url.origin || "";
    const cors = ALLOWED_ORIGINS.includes(origin) ? {
      "Access-Control-Allow-Origin": origin,
      "Access-Control-Allow-Methods": "GET,OPTIONS",
      "Access-Control-Allow-Headers": "Content-Type"
    } : {};
    ```
    - CORS is only populated when the Origin header matches the known worker URL.
    - GET and OPTIONS methods only (POST CORS is unnecessary — pipeline uploads are not browser-initiated).
    - The `...cors` spread in existing route handlers will become an empty object for unknown origins, effectively removing the headers.
    - OPTIONS preflight response uses `new Response(null, {headers:cors})` — if cors is empty, the preflight still succeeds but without CORS headers (browser will reject it for cross-origin requests, which is correct).

    **Why not `*`:** Prevents any website from making authenticated fetches to the API. Since the dashboard is same-origin, `Same-origin` requests don't need CORS at all.

        """Call fn() with exponential backoff. Re-raises last exception after max_retries."""
        for attempt in range(max_retries):
            try:

            except urllib.error.HTTPError as e:

                if attempt < max_retries - 1:
                    delay = base_delay * (2 ** attempt)
                    log(f"  [재시도 {attempt+1}/{max_retries}] network error: {e}, waiting {delay}s...")
